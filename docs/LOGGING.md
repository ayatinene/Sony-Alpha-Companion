# 日志与诊断说明

入口：设置 → 记录级别；设置 → 导出日志与诊断。

## 记录级别

所选级别是最低记录门槛（例如选 `INFO` 会记录 `INFO`、`WARN` 和 `ERROR`）：

| 级别 | 记录内容 |
|---|---|
| `TRACE` | `DEBUG` 的全部内容，外加有限长截断的 HTTP JSON/XML 协议响应文本 |
| `DEBUG`（默认） | 请求编号、PTP 事务与参数、状态码与耗时、扫描进度、后台服务所有权、生命周期、取景统计与传输进度 |
| `INFO` | 连接、PTP 会话打开/关闭、扫描完成、拍照、文件开始/完成下载、导出诊断等主要操作 |
| `WARN` | 取景断流、下载重试、状态查询异常、`OpenSession` 已有会话拒绝（`0x201E`）、后台服务受限等可恢复问题 |
| `ERROR` | 最终失败与保留原始底层异常的完整原因链 |

日志在后台写入文件，按 512 KiB 轮转并保留两份备份（共约 1.5 MiB）。取景帧统计、扫描进度和下载进度已做节流；手动取消的请求记为 `DEBUG`，与最终失败区分。PTP/IP 传输异常会保留首次触发的底层 `IOException` / 协议异常原因链，不会被后续关闭动作的通用 `"Connection closed"` 覆盖。协议响应文本和单条异常堆栈均有限长限制，避免单次大响应刷满日志。

## 导出内容

导出的文件名为 `AlphaCompanion-模式-日期-时间-毫秒.zip`，包含：

- `logs/app.log`：当前日志。
- `logs/app.1.log`、`logs/app.2.log`：存在时的历史轮转日志。
- `diagnostics.json`：应用版本与构建提交（`app`、`versionCode`、`gitRevision` 短 SHA 及本地 `-dirty` 标记、与“设置 → 关于与许可”一致的 `appVersion`）、设备信息、最近连接相机的机内应用与能力、当前连接会话与 RAW 扫描状态快照、最近协议响应、未完成下载状态快照，以及日志级别、丢弃数和写入失败数。
- `last-crash.txt`：存在时的最近一次未捕获崩溃堆栈（覆盖安装后会保留历史文件，排查时请核对堆栈与日志时间，区分如 `0.1.7` 等旧版遗留崩溃记录与当前版本运行日志）。

## 隐私与排查建议

诊断包不会导出照片原文件字节、实时取景画面帧、Wi-Fi 密码或接收端 GUID（PTP/IP 初始化握手包负载与对象字节已在日志层脱敏省略）；但日志和 `diagnostics.json` 可能包含照片文件名、局域网 IP 或相机服务 URL，公开分享前请留意。

一般排查保持默认的 `DEBUG` 即可。如果需要查看协议返回的 JSON/XML 文本，先在设置里切到 `TRACE` 再复现问题，结束后立即导出 ZIP。遇到闪退时，重新打开应用后先不要连接相机，直接去设置导出诊断，就能拿到闪退前的日志和 `last-crash.txt`。

# 日志与诊断

设置 → 记录级别；设置 → 导出日志与诊断。

## 等级

| 等级 | 内容 |
|---|---|
| TRACE | DEBUG 的内容，加 HTTP JSON/XML 协议响应文本 |
| DEBUG（默认） | 请求标识、状态和耗时、生命周期、取景统计与传输进度 |
| INFO | 连接、拍照、文件开始/完成、导出等主要动作 |
| WARN | 断流、重试、状态查询异常等可恢复问题 |
| ERROR | 最终失败与完整异常原因链 |

所选等级是最低记录等级。例如 INFO 会记录 INFO、WARN 和 ERROR。TRACE 不记录照片、取景帧或原始 PTP 数据包；协议文本和单条堆栈有限长，避免个别响应占满日志。

## 导出

文件名为 `AlphaCompanion-模式-日期-时间-毫秒.zip`，内容包括：

- `logs/app.log`：当前可读日志。
- `logs/app.1.log`、`logs/app.2.log`：存在时的较早日志。
- `diagnostics.json`：设备、机内应用、能力、协议响应和传输队列快照，以及日志级别、丢弃数和写入失败数。
- `last-crash.txt`：存在时的最近一次应用崩溃堆栈。

日志行包含带时区的时间、等级、模块、线程、运行会话和相机模式。HTTP 请求有独立编号和耗时；取消请求记为 DEBUG，与最终失败区分。日志按 512 KiB 轮转并保留两份备份，总量约 1.5 MiB；文件写入在后台完成。

复现问题前保持 DEBUG。若需更详细协议过程，先改为 TRACE 再复现，结束后立即导出 ZIP。发生闪退时，重启应用后先不连接相机，直接导出，便可保留重启前的日志和最近崩溃信息。反馈问题时附上完整 ZIP 即可。
